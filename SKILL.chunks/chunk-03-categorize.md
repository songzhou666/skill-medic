# Chunk 03：三维分类

> 加载条件：`phase == MED_SORT`

## 分类原则（软约束，§4.3）

- **功能域是开放语义域**：用户可能安装任何行业的 Skill（医疗、金融、法律、教育、电商……）。
  分类**不以静态关键词表为准**——关键词表只对"已知域"提供启发式提示（`domain_hint` + `domain_evidence`），
  未命中时**不得**判"其他"，必须由 LLM 基于 description + 正文语义判定，且允许创造新域标签。
- **交互模型 / 生命周期**：基于确定性结构信号（tools 目录 / mcp-reference / CHANGELOG / 设计文档），
  静态初值可信，LLM 可结合正文修正。
- 每个分类标签必须带 evidence（来源 description 或正文行），供 05-auditor 复核。

## 分类流程

1. 读取 `_medic_inventory.json`（含 `run.py categorize` 产出的 `domain_hint` / `interaction` / `lifecycle`）
2. LLM 逐 Skill 语义判定功能域（`domain_final`），参考但不盲从 `domain_hint`：
   - `domain_hint` 有值且语义吻合 → 采纳，evidence 沿用 + 可补充
   - `domain_hint` 有值但语义不符 → 覆盖，必须记录"初值 → 修正值 + 理由"
   - `domain_hint` 为空 → LLM 基于正文自主判定并写 evidence
3. 交互模型 / 生命周期：确认静态初值，异常时修正（留理由）
4. 同一功能域的 Skill 标记为同组（后续冲突检测的分组基础）

## 功能域（开放集合，示例标签）

| 示例标签 | 判定依据（仅示例，不穷举） |
|---------|---------------------------|
| 系统探索采集 | 浏览器/页面/数据采集、工单解析 |
| 数据分析报表 | 数据合并、统计、可视化渲染 |
| 文档与手册 | 操作手册、开发文档、知识捕获 |
| 设计创意 | 游戏策划、内容创作 |
| 风格定制 | AI 对话风格配置 |
| 项目流程 | 需求/开发/测试全流程管理 |
| 质量保障 | 代码审查、安全扫描、调试 |
| Skill 工程 | 创建/检查/审计 Skill |
| 系统维护 | 磁盘清理、系统优化 |
| **新域（LLM 创造）** | 如"医疗文书生成""法律合同审查"，只要 evidence 成立即可 |

> **铁律**：表中列出的只是**已知示例**。遇到不在表中的业务域，LLM 必须创造新标签，
> 禁止因为"不在表里"而强行塞进相近域或判"其他"。

## 交互模型（固定六类）

| 取值 | 判定依据 |
|------|----------|
| 浏览器驱动型 | references/mcp-reference.md 存在，或 description 含 CDP/Playwright/browser_ 等精确词 |
| 数据库驱动型 | description 含 MySQL/数据库/DB 连接/sqlite 等**通用技术词**（具体库名/表名是环境数据，不参与交互模型判定，由 C4 检测从代码通用提取） |
| 网络API型 | description 含 Gitea/COS/WebSearch 等精确词 |
| 脚本工具型 | 有 `*_tools/` 或 `tools/` 目录 |
| 纯提示词型 | 无工具目录且无上述命中 |
| 混合型 | 同时具备多种模式（LLM 判定） |

## 生命周期状态（固定五类）

| 取值 | 判定依据 |
|------|----------|
| 活跃维护 | 有 CHANGELOG 且近期有更新痕迹 |
| 维护停滞 | 无更新痕迹 |
| 开发中 | 仅有设计稿（_design.md / 设计需求文档.md） |
| 备份归档 | 仅 zip 包 |
| 已发布 | 全局同步可用 |

## 输出格式

每个 Skill 输出三维标签 + evidence，形如：
`example-skill | 文档生成 · 纯提示词型 · 活跃维护 | evidence: description L1"生成操作手册"`
