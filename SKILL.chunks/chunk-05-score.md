# Chunk 05：八维评分细则

> 加载条件：`phase == MED_VITAL`

## 批分组依据（渐进式批量）

1. **分组键 = `domain_final`**（02-classifier 的 LLM 语义判定结果，非静态 `domain_hint`）：
   - 读取 `.medic/_medic_classify.json`，用 `domain_final`（LLM 已回填）或 `domain_hint`（未回填时兜底）分组
2. 每组 ≤3 个 Skill 成一批；跨组冲突对单独成批（≤3 对/批）
3. 每批正文估算预算 ≤10k token；单 Skill 超限 → 分段抽样（每段 ≤5k、最多 3 段）
4. 批间进度**不写接力棒**：每批完成后回报 00-master，由主控代写 `batch` 段（单点写）
5. 失败隔离：单批失败自动重试 1 次，仍失败标记 skip 继续，收尾汇总未完成批

## 评分流程

1. `medic_tools/run.py score <root> <skill> --save` 输出**八维静态证据信号**（`static_score_signals`）：
   - 每维的候选命中词（触发/流程/异常/产出/边界/工程/维护）+ 结构信号（has_chunks/tokens/has_tools 等）
   - 只做抽象信号检测，不读业务逻辑、不读配置值
   - `--save` 累积落盘 `.medic/_medic_scores.json`
2. LLM 对照八维细则，**结合静态信号 + 抽样正文**逐维打分 + 证据 + 扣分定位；
   **打分结果必须用 IDE Write 工具写回 `.medic/_medic_scores.json`**（保留 CLI 已写的该 Skill 顶层信号块
   `{skill_base: {name, status, dim1...}}`，把 LLM 打分追加到该条目的 `llm_scores` 键——
   `llm_scores: {score, level, per_dim, evidence}`，**禁止整文件覆盖或改顶层键名**，
   否则下一次 `run.py score` 读-改-写会损坏备份重建、丢失已累积分数）
3. 05-auditor-agent 抽查 ≥30% Skill

## 静态信号与八维对照

| 维度 | score 命令给出的信号 |
|------|---------------------|
| 1 触发契约 | desc_len、desc_has_antitrigger、dim1_trigger（触发/反触发词命中） |
| 2 流程机制 | dim2_flow（阶段/节点/分支词命中） |
| 3 异常与熔断 | dim3_exception（追问/终止/重试/回退词命中） |
| 4 产出控制 | dim4_output（checklist/自检/验收词命中） |
| 5 边界与上下文 | dim5_boundary（上限/分块词命中 + has_chunks + tokens_est） |
| 6 内容价值密度 | dim6_value_weak（弱信号：chars/tokens/has_refs；语义判定以 LLM 为准） |
| 7 工程配套 | dim7_engineering（has_tools/manifest/readme/protocols） |
| 8 维护健康度 | dim8_maintain（has_changelog/version/has_readme） |

> 信号命中 ≠ 得分：命中词是"候选证据"，由 LLM 判断证据是否成立、给分多少。
> 信号为空是**真实扣分线索**（如 dim4 无自检词 → 产出控制维需重点检查）。

|---|------|:---:|---------|-------------|

## 成熟度联动（阈值固定，禁止改动）

> **评级衡量的是 Skill 的"可靠性 / 完成度"**——能不能稳定地把它承诺的功能执行到位、达到你的目的；
> **不是"安不安全"**（数据安全与合规是另一回事，不在本评分内）。

| 级别 | 通俗名称 | 得分范围 | 准确含义（报告/对话用） |
|------|---------|:--------:|------------------------|
| L3 | 放心用 | ≥ 80 分 | **能稳定完成它承诺的功能**：说明完整、流程可控、异常处理到位、边界清晰；复杂场景也可靠，出问题能自己兜住（有回退/熔断） |
| L2 | 基本能用 | 55~79 分 | **常规场景能完成功能**，但缺异常处理/自检/边界说明；遇到缺信息、复杂输入或异常情况可能出错或跑偏，需要你多检查 |
| L1 | 不太成熟 | 30~54 分 | **只能处理理想样例**，真实业务容易翻车；可能达不到你要的效果，重要任务别依赖 |
| L0 | 不建议用 | < 30 分 | **基本不可用**（缺关键文件/长期无人维护/无法完成核心任务）；用了大概率白折腾，建议修复或删除 |

> 面向用户的输出（报告/回复）**必须**用"准确含义"栏，L0~L3 标签只作为括号备注，如"放心用（L3）"。
> 四档对应的八维判据：L3=八维均健全；L2=核心流程完整但异常/边界/工程薄弱；L1=只有流程骨架或纯模板；L0=连骨架都不完整。

## 评分规则（口径强约束，禁止自创）

- **每维给分上限 = 该维满分（权重值）**：如 D1 满分 15，只给 0~15 分；**禁止**"每维先打 0-100 再加权"等自创口径
- **总分 = Σ 各维实得分**（满分 100）
- **定级阈值固定**：L3≥80 / L2 55~79 / L1 30~54 / L0<30，禁止按个人标准调整
- 每维给分 + 一句话证据 + 扣分定位（文件/章节）
- 静态指标与 LLM 结论冲突时，以证据为准并标注矛盾
- 单 Skill 正文估算 token > 30k → 降级为分段抽样（每段 ≤5k，最多 3 段）
