# Chunk 01：总览与状态机

> 加载策略：always — 本 chunk 随 Skill 激活常驻加载。

## 本 Skill 一句话

**SkillMedic** 帮你把装的一堆 Skill 查清楚：先列出都有谁（清单），再按用途分组（分类），然后揪出"谁和谁重复、谁会抢着响应同一个请求"（冲突），最后评估每个 Skill 靠不靠谱（成熟度），给出"留谁、并谁、改谁、删谁"的建议（处方）。

## 8 阶段状态机

```
MED_SCOPE → MED_ROSTER → MED_SORT → MED_CONFLICT → MED_VITAL → MED_RX → MED_DEBRIEF → MED_CLOSE
```

### 阶段闸门规则

- 进入下一阶段前必须验证上一阶段产出存在且非空
- 无 `inventory_json` 禁止进入 MED_SORT
- 无 `conflict_matrix` 禁止进入 MED_VITAL
- 接力棒由 00-master-controller 统一更新，子 Agent 禁止直接修改

### 断点续跑

中断后再次调用，先做**产物回退校验**（✅ 阶段产物缺失 → 回退重做），再对含审核闸门的阶段（`gateN` 为 ⬜ 或被打回重做）**强制重跑 05-auditor** 一次，然后从第一个 ⬜ 阶段继续（详见 00-master-controller 启动流程）。
**S3/S4 档**：07-reporter 逐域回填中断后按接力棒 `batch.appendix_done` 从未完成域继续；档位在 MED_ROSTER 后写入 `meta.scale`（S1~S4），各阶段沿用。
**MED_DEBRIEF 续跑**：该阶段中断后**禁止重跑 `run.py report`**（重跑会覆盖 07 已回填的附录与 7.2/附录内容），直接按 `batch.appendix_done` 从未回填域继续；若报告/附录文件不存在才重跑 report。

### 专项模式（用户指定"只查冲突/只打分"等）

| 模式 | 执行阶段 | 跳过阶段 | 报告输出 |
|------|---------|---------|---------|
| 只查冲突 | MED_SCOPE→MED_ROSTER→MED_SORT→MED_CONFLICT | MED_VITAL/MED_RX/MED_DEBRIEF 中的评分与处方部分 | 第 1/3/5 部分 + "专项检查（未覆盖评分与处方）" |
| 只打分 | MED_SCOPE→MED_ROSTER→MED_SORT→MED_VITAL | MED_RX/MED_DEBRIEF 中的处方部分 | 第 1/3/4/6 部分 + "专项检查（未覆盖处方）" |
| 范围限定 | 仅 workspace / 仅 global（`run.py scan --scope` 过滤）/ 追加自定义目录（`--extra-dir`） | 另一范围 | 元信息标注"扫描范围：仅 xxx" |

- 专项模式被跳过阶段的**产物与闸门豁免**（不验证、不强求），但必须在报告元信息标注"专项检查（未覆盖 xxx）"；
- 专项模式不走 8 阶段全链，00-master 按裁剪表路由，跳过闸门不触发 05 审核（单段产出自检即可）。

### 严格模式（用户指定"严格模式"：评分/审核从严）

在默认全量流程基础上，从严档位只调整以下差异项（其余规则与默认一致）：

| 差异项 | 默认模式 | 严格模式 |
|--------|---------|---------|
| 评分证据 | 弱信号也可作为候选，LLM 判断 | **只有强证据才给分**：单维证据不足（仅命中词无正文佐证）→ 该维 0 分并标注"证据不足" |
| 待确认标注 | 证据不足的结论标注"待确认" | **低证据一律标注"待确认"**（含 C1 定级、八维中任何证据薄弱维度） |
| 05 抽检比例 | ≥30% Skill | **≥50% Skill**；所有高严重度冲突证据逐条复核 |
| 冲突精析 | S3/S4 档低严重度对可跳过不精析 | **S1~S4 全部冲突对逐对精析**（不享受大规模档"跳过低严重度"豁免） |
| 定级阈值 | L3≥80/55~79/30~54/<30（固定） | 同一套固定阈值（**不可改变**，严格模式只严证据、不严分数线） |

- 严格模式由 00-master 路由时传给 04-scorer 与 05-auditor；05-auditor 按严格档位执行抽检与证据复核；
- 报告元信息标注"严格模式"。

### 增量审计（用户指定"对比上次/增量检查"）

1. 执行 `run.py diff <root>` 读取 `.medic/_medic_last_inventory.json` 对比，得到 added/removed/changed
2. **裁剪全链**：MED_SORT/MED_CONFLICT/MED_VITAL/MED_RX 只对 added/changed 项执行，unchanged 沿用上次评分并标注"沿用"；
   removed 项只在报告第 8 部分"已消失 Skill"中体现
3. 报告第 8 部分输出差异清单（新增/变更/移除）与"上次处方执行核对"
4. 缺上次清单（首次审计）→ 提示"无上次清单，回退全量审计"

### 熔断

- 子 Agent 超时（120s）→ 自动重试 1 次 → 仍失败则记录 last_error，`state=FAILED`（is_running 保持 1，由下次调用按状态异常处理恢复，**非死局**）
- 同一阶段/闸门累计重试 ≥3 次 → `state=FAILED` 并停止自动重试，转人工
- **执行说明**：本 Skill 由同一 AI 按提示词切换角色执行、无独立子进程计时器——"超时 120s"由**平台运行超时机制**接管
  （AI 侧以"单批执行超过上下文预算/步骤异常增多"作为等价信号，按重试/熔断规则处理）

## 命名空间

全部阶段/节点/产物统一使用 `MED_` / `_medic_` 前缀，不与任何现有 Skill 撞名。
