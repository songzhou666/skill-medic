# 07-reporter-agent：报告生成

## 职责

生成 **Skill 检查报告**（面向普通用户）并落盘。

## 执行规则

1. 汇总各阶段产物为完整报告（双层：元信息 / **编号 1 人话汇报层** / 编号 2~9 专业明细层：总览 / 清单 / 分类 / 冲突与问题 / 评分 / 行动建议明细 / 历史对比 / 标准对照）
2. **必须回填**（LLM 智能分析层）：
   - **第 1 部分汇报层（人话版）**：
     - 1.1 健康度总评：一句话总评 + 分布条（放心用 █ 7 ｜ 基本能用 █ 5 ｜ 不太成熟 █ 1 ｜ 不建议用 █ 1）
       + **分级名单（逐个点名）**：把每个 Skill 的名字归入四档（放心用 L3 / 基本能用 L2 / 不太成熟 L1 / 不建议用 L0），
       没有则写"无"——**必须从第 6 部分评分表推导**，禁止另写一套分布
       + **使用局限**：对"不太成熟 / 不建议用"档的 Skill 各补一句"什么场景下容易出问题、别用它做什么"
     - 1.2 TOP 问题榜 3~5 条：问题一句话 / 影响你什么 / 建议怎么办（建议必须是**使用类**，如"以后都用 A"）
     - 1.3 最该做的 2~3 件事（**如果你是使用者**）：从 **7.1 使用建议**挑最高优先级，**只给不用改文件的使用类建议**（如"别用 XX 处理正式数据"）
   - **7.1 使用建议（必写）——面向"使用者"**：覆盖"注意什么 / 有什么风险 / 什么需求别指望它"，每条都是不用改文件、直接照做的操作
   - **冲突影响**：每个冲突补"影响你什么"（日常语言 + 自然语言唤醒举例，见 chunk-07 示例）
   - **评分定级**：用通俗格式"放心用（L3）/ 基本能用（L2）/ 不太成熟（L1）/ 不建议用（L0）"，与第 6 部分一致
   - **7.2 改造建议精确操作——面向"创建者 / 维护者"**：补文件路径 + 改动内容 + 执行方式 + 优先级，标注"使用者可完全跳过本节"
   - **历史洞察**："上次的问题解决了吗"
3. 强制落盘 `.medic/skill_audit_report_{时间戳}.md`（目录自动创建）
4. 主回复同步输出完整报告
5. 不写数据库

## 报告格式铁律（防止回填时走样）

1. **0.1 图例区是固定区块，最终报告必须保留**，不得删减或改写
2. **定级阈值必须引用 chunk-05 固定值**（L3≥80 / L2 55~79 / L1 30~54 / L0<30），禁止自创（如 75/55/35），
   分级名单、健康度分布、第 9 部分定级规则三者口径必须一致
3. 1.1 分级名单/健康度分布、1.2 TOP 榜、7.1 使用建议必须从明细层推导，禁止另写一套

> 报告双层原则：编号 1 = 结论先给、大白话；编号 2~9 = 专业数据与证据完整保留。
> 汇报层与明细层是"结论 ↔ 证据"关系：结论可简化、不可矛盾（05-auditor BLOCK-E 核对）。
> 报告面向普通用户：避免只写专业术语（C1~C5 / L0~L3 / 八维），术语作括号备注，
> 主表达用日常语言；每类问题都要让用户明白"这会影响我什么、我该怎么做"。

## MED_CLOSE 阶段

1. 更新接力棒（state=CLOSE, is_running=0），`history` 记录本次报告路径
2. **仅当会话全部完成**时执行 `run.py cleanup`（清理本次会话中间产物 classify/conflicts/scores/rx；
   **保留 `_medic_inventory.json` 与历史报告**——增量模式/历史对比的基础）
3. **中断续跑前禁止 cleanup**：is_running=1 时中间产物必须保留，否则闸门验证会断
4. 输出完成摘要给用户
