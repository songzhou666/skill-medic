# 冲突类型目录 — C1~C5

## C1：同质冲突（功能重复）

两个及以上 Skill 功能域高度重叠，各自维护成本浪费且触发路由随机。

**检测信号**：
- description/功能点相似度 ≥ 阈值
- 目录结构、阶段名、产出物命名高度雷同

**示例**：
- 同功能的两个风格定制 Skill（都是"AI 对话风格配置"）
- 同功能的两个游戏设计 Skill（都是"游戏 GDD 设计"）

## C2：意图抢占（误触发）

同一用户请求可命中多个 Skill，路由不确定。

**检测信号**：
- description 触发面重叠（关键词交集大）
- 缺少"何时不要调用"反触发说明

**示例**：
- 多个浏览器探索类 Skill（"探索系统/扫描页面"类请求容易误触发）

## C3：上下文膨胀（Token 黑洞）

Skill 常驻加载体积过大、无分层加载，挂载后显著抬高每轮成本、稀释整体能力。

**检测信号**：
- 常驻加载量（SKILL.md + load:always 的 chunk 索引）估算 token 超阈值
- 无 chunk 分层
- 正文含大量通用常识

## C4：依赖/引用冲突

共享数据、配置、接力棒，一方改动静默破坏另一方。

**检测信号**：
- 引用同一 config.json / 同一 DB 表 / 同一 baton 路径 / 同一环境变量
- 双方实现 mtime 差异明显（一方改动未同步）

**示例**：
- 多个 Skill 共享同一接力棒目录与同一数据库（一方改表结构静默影响其他方）

## C5：资源竞争

同一物理/逻辑资源被多个 Skill 抢占，无法并行。

**检测信号**：
- 都声明浏览器/CDP
- 同一 MCP 工具
- 同一端口

> 注：同一库表写入权归 **C4 依赖冲突**（DB 表/库引用从代码通用提取归入 C4），C5 只检物理/逻辑运行时资源（浏览器/CDP/MCP 工具/端口）。
